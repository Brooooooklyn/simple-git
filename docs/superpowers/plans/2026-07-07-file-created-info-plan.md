# Plan: add `created` to `FileModification`

## Goal

Give the file-history API "the same info for file creation" that it already has
for last-modification. Add ONE new field, `created`, to the `FileModification`
object. It carries the full commit metadata of the commit that **first added**
each file. The existing methods that return `FileModification`
(`getFileLatestModified` / `getFilesLatestModified`, sync + async) populate it.

No new public methods. No breaking changes to existing fields.

## Design

```
CommitInfo (NEW struct — same 8 fields as FileModification's commit fields)
  commitId, summary, authorName, authorEmail, authorTime,
  committerName, committerEmail, committerTime

FileModification (existing) gains ONE field:
  ...existing 8 flat fields = the LAST-MODIFYING commit (unchanged)...
  created: CommitInfo | null   ← NEW: the commit that first ADDED the file
```

### Why a separate walk (the "best way", benchmark-proven)

Latest-modified and creation resolve fastest walking in **opposite** directions,
so each gets its own early-exiting walk; the results are merged afterward.

```
last-modified  ── existing get_files_modification / get_file_modification (UNCHANGED)
                  newest→oldest, diff vs parent under pathspec, early-exit at first touch

created        ── NEW get_files_creation / get_file_creation
                  Sort::TOPOLOGICAL | Sort::REVERSE  (oldest→newest, ancestors first)
                  FIRST commit whose tree contains the exact path = creation → early-exit
                  bulk: unresolved-set, break when empty

merge          ── attach `created` to each FileModification that has a record
```

A single combined walk would kill early-exit for one direction (forcing a full
history walk). An empirical benchmark on this repo's real history confirmed:
`TOPOLOGICAL | REVERSE` yields a valid ancestors-before-descendants order (0
violations across 233 commits incl. 4 merges), returns the exact same creation
OID as the current `getFileCreatedDate` and as `git log --diff-filter=A`, and
processes far fewer commits (233→1 for root-era files).

### Semantics

- `created` = the **oldest** commit whose tree contains the exact path.
- delete → re-add: reports the **original** add, not the re-add (benchmark-confirmed).
- merge commits **are** included in the creation walk (tree-containment).
- no rename-follow (same documented TODO as the rest of the file-history API).
- times use committer time via `time_to_date(commit.time().seconds())`, matching
  the existing flat fields.
- exact-path resolution (`tree.get_path`), like `getFilesLatestModified`. When
  `getFileLatestModified` is given a glob/directory, the flat fields resolve via
  pathspec but `created` may be `null` — documented.

### File map

```
src/file_modification.rs   CommitInfo struct; created field; build_commit_info;
                           get_file_creation; get_files_creation;
                           get_file_modification_with_created;
                           get_files_modification_with_created
src/repo.rs                get_file_latest_modified (sync) + GitModificationTask.run
                           get_files_latest_modified (sync) + GitBulkModificationTask.run
                           → all four call the *_with_created wrappers
index.js / index.d.ts      regenerated by `yarn build:debug` (never hand-edited)
__test__/modification.spec.mjs   new tests
```

## Global Constraints

These bind every task. Copy them into each implementer and reviewer dispatch verbatim.

- **GC1 — Regenerate & commit napi bindings.** After any Rust change, run
  `yarn build:debug` (it runs `napi build --platform`, regenerating `index.js`,
  `index.d.ts`, and the `.node` binary). Commit `index.js`/`index.d.ts` exactly
  as generated. NEVER hand-edit them.
- **GC2 — Creation-walk sorting.** The creation walk MUST use
  `git2::Sort::TOPOLOGICAL | git2::Sort::REVERSE` (oldest-first). Do NOT include
  `Sort::TIME`. First commit whose tree contains the exact path = creation;
  early-exit on first hit (single) / when the unresolved set empties (bulk).
- **GC3 — Two separate walks, not one.** `created` MUST come from the reverse
  creation walk, SEPARATE from the newest-first modification walk. Do NOT fold
  creation detection into the modification walk. Merge the two results afterward.
- **GC4 — `created` only for present records.** Compute/attach `created` only
  for paths that already have a modification record (`Some`). Never-committed
  paths stay `null` (whole record) and are excluded from the creation walk.
- **GC5 — Exact-path creation.** `created` resolves by EXACT repo-root-relative
  path via `tree.get_path`, NOT pathspec/glob. Document the glob/directory caveat
  on the single-file method.
- **GC6 — Semantics.** `created` = oldest commit containing the path (first-ever
  add; delete→re-add returns the original). Merges included in the creation walk.
  No rename-follow. Committer time via `time_to_date(commit.time().seconds())`.
- **GC7 — Async parity + state restore.** Async task `run()`s MUST produce
  results identical to their sync counterparts by calling the SAME
  `*_with_created` wrapper, AFTER `reopen_worker_repo` +
  `restore_worker_handle_state` (namespace/workdir/flags).
- **GC8 — DRY.** Factor the modification+creation merge into shared helpers
  (`get_file_modification_with_created`, `get_files_modification_with_created`)
  in `src/file_modification.rs`, called by BOTH the sync methods and the async
  `run()`s. Route `build_modification` through `build_commit_info` so the 8-field
  extraction is written once.
- **GC9 — __proto__-safety.** Bulk result still returns via `FileModMap`
  (own-property define semantics). The existing `__proto__`/`constructor`
  regression tests must still pass unchanged.
- **GC10 — Error handling.** Sync methods and async tasks apply
  `.convert_without_message()` to the wrapper result, matching the existing
  modification methods. Do NOT invent new error messages for the walk.
- **GC11 — Verification.** Every task runs `yarn build:debug` then `yarn test`
  and reports the full ava output. Cross-check `created` against git ground
  truth `git log --diff-filter=A --format=%H --reverse -- <path> | head -1`
  where feasible; skip strict CLI parity under `process.env.CI` (mirror existing
  tests).

## Task 1: Core types + single-file `created` (TDD)

**Files:** `src/file_modification.rs`, `src/repo.rs`, `__test__/modification.spec.mjs`, regenerated `index.js`/`index.d.ts`.

Establish the shared types and wire the SINGLE-file path end to end.

### Step 1 — RED (write failing tests first)

In `__test__/modification.spec.mjs`, add tests against the real repo:

- `getFileLatestModified("build.rs").created` is a truthy object whose
  `commitId` matches `/^[0-9a-f]{40}$/`, with `created.authorTime` /
  `created.committerTime` instances of `Date`.
- Non-CI value parity: `created.commitId` equals
  `git log --diff-filter=A --format=%H --reverse -- build.rs | head -1` (the
  first commit that added the file). Under `process.env.CI`, just assert the
  shape (truthy object, 40-hex commitId) since the checkout may be shallow.
- `getFileLatestModifiedAsync("build.rs")` deep-equals the sync result
  (so `created` matches too).
- Missing path: `getFileLatestModified("does-not-exist-xyz.txt")` is `null`
  (unchanged — no `created` to attach).

Run `yarn test` and confirm these FAIL (`created` is `undefined`) before implementing.

### Step 2 — GREEN (implement)

In `src/file_modification.rs`:

1. Add a `#[napi(object)] pub struct CommitInfo` with the same 8 fields as
   `FileModification`'s commit fields (`commit_id`, `summary`, `author_name`,
   `author_email`, `author_time`, `committer_name`, `committer_email`,
   `committer_time`), with doc comments describing them as the CREATING commit.
2. Add `pub created: Option<CommitInfo>` to `FileModification`, doc-commented per
   GC5/GC6 (oldest commit that first added the file; `null` when the file has no
   ordinary-commit history or when a glob/directory was passed to the single-file
   method).
3. Add `pub(crate) fn build_commit_info(commit: &git2::Commit) -> Result<CommitInfo, git2::Error>`
   holding the 8-field extraction (moved out of `build_modification`). Have
   `build_modification` call `build_commit_info` and add `created: None` (GC8).
4. Add `pub(crate) fn get_file_creation(repo, filepath: &str) -> Result<Option<CommitInfo>, git2::Error>`:
   revwalk from HEAD, `set_sorting(git2::Sort::TOPOLOGICAL | git2::Sort::REVERSE)`,
   for each oid: `find_commit`, `tree()`, `tree.get_path(path)` →
   `Ok(_) => return Ok(Some(build_commit_info(&commit)?))` (first/oldest hit),
   `Err(NotFound) => {}`, `Err(e) => return Err(e)`. Return `Ok(None)` if never
   found. Mirror the existing walks' error-propagation comments.
5. Add `pub(crate) fn get_file_modification_with_created(repo, filepath: &str) -> Result<Option<FileModification>, git2::Error>`:
   `get_file_modification(repo, filepath)?`; if `Some(mut fm)`, set
   `fm.created = get_file_creation(repo, filepath)?` and return `Some(fm)`; else
   `None` (GC3/GC4).

In `src/repo.rs`:

6. `get_file_latest_modified` (sync): call
   `get_file_modification_with_created(self.inner()?, &filepath).convert_without_message()`.
7. `GitModificationTask::run`: after reopen + restore, call
   `get_file_modification_with_created(&repo, &self.filepath).convert_without_message()`.

Then per GC1/GC11: `yarn build:debug` (regenerate + commit `index.js`/`index.d.ts`),
`yarn test`. All new + existing tests pass. Confirm `index.d.ts` now shows the
`created` field on `FileModification` and a `CommitInfo` interface.

### Done when

`yarn build:debug` compiles, `yarn test` is fully green (new single-file
`created` tests pass, all pre-existing tests still pass), bindings regenerated
and committed.

## Task 2: Bulk `created` (TDD)

**Depends on Task 1** (uses `CommitInfo`, `build_commit_info`, the `created`
field, and the `_with_created` pattern).

**Files:** `src/file_modification.rs`, `src/repo.rs`, `__test__/modification.spec.mjs`, regenerated bindings.

### Step 1 — RED

Add tests:

- `getFilesLatestModified(["build.rs","Cargo.toml","bogus-zzz.txt"])`: for each
  present path, `result[path].created` deep-equals
  `getFileLatestModified(path).created`; `result["bogus-zzz.txt"]` is `null`.
- Async bulk `getFilesLatestModifiedAsync(paths)` deep-equals sync bulk (so
  `created` matches across the async boundary).
- Extend / confirm the existing `__proto__` and `constructor` regression tests
  still hold with `created` present (a present `__proto__` path's record now also
  carries a `created` object; prototype still intact — GC9).

Run `yarn test`; confirm the new bulk `created` assertions FAIL before implementing.

### Step 2 — GREEN

In `src/file_modification.rs`:

1. Add `pub(crate) fn get_files_creation(repo, filepaths: &[String]) -> Result<HashMap<String, Option<CommitInfo>>, git2::Error>`:
   seed `result` (each path→`None`) and an `unresolved: HashSet`; empty-input
   early-return; revwalk from HEAD with
   `Sort::TOPOLOGICAL | Sort::REVERSE`; for each commit, `break` when
   `unresolved` is empty, else for each still-`unresolved` path probe
   `tree.get_path` → on `Ok` insert `Some(build_commit_info(&commit))` and remove
   from `unresolved` (first/oldest containing commit wins), `NotFound` skip,
   other error propagate. Follow the structure of `get_files_modification`'s
   root-commit branch, but over ALL commits (merges included) and oldest-first.
2. Add `pub(crate) fn get_files_modification_with_created(repo, filepaths: &[String]) -> Result<HashMap<String, Option<FileModification>>, git2::Error>`:
   `get_files_modification(repo, filepaths)?` → `mods`; collect the paths whose
   value is `Some` into `present`; if non-empty, `get_files_creation(repo, &present)?`
   and for each `(path, creation)` set the record's `created` via
   `mods.get_mut(&path)` (GC3/GC4).

In `src/repo.rs`:

3. `get_files_latest_modified` (sync):
   `get_files_modification_with_created(self.inner()?, &filepaths).map(FileModMap).convert_without_message()`.
4. `GitBulkModificationTask::run`: after reopen + restore, call
   `get_files_modification_with_created(&repo, &self.filepaths).convert_without_message()`.

Then `yarn build:debug` (regenerate + commit bindings), `yarn test` — all green.

### Done when

`yarn build:debug` compiles, `yarn test` fully green (bulk `created` tests pass,
`__proto__`/`constructor` regressions still pass, all pre-existing tests pass),
bindings regenerated and committed.

## Task 3: Semantics & edge-case tests + docs

**Depends on Tasks 1 & 2.**

**Files:** `__test__/modification.spec.mjs`, doc comments in `src/file_modification.rs`
and `src/repo.rs` (which regenerate `index.d.ts`).

### Step 1 — Hermetic multi-commit tests (the point of the feature)

Add a helper that builds a throwaway repo with a controlled multi-commit history
(the existing `makeRepo` makes a single commit; add e.g.
`makeRepoWithHistory(steps)` where each step is a set of file writes + a commit,
run via the same `git init`/`config`/`add`/`commit` pattern, returning
`{ root, repo }`). Then:

- **created ≠ lastModified** — build history: commit C1 adds `f.txt`; commit C2
  modifies `f.txt`. Assert `repo.getFileLatestModified("f.txt")`:
  `.created.commitId` equals C1's hash, `.commitId` equals C2's hash, and the
  two differ. This is the core value of the feature — creation is distinct from
  last modification. Cross-check C1/C2 via git CLI in the throwaway repo.
- **delete → re-add** — C1 adds `g.txt`; C2 deletes it; C3 re-adds it. Assert
  `.created.commitId` equals C1 (the ORIGINAL add), not C3 (GC6).
- **root-only file** — a file present only in the seed/root commit: assert
  `.created.commitId === .commitId` (creation == last-modification for a
  single-commit file). Can reuse `makeRepo(["only.txt"])`.
- **bulk creation matches single** on a multi-commit repo — for the C1/C2 file,
  `getFilesLatestModified(["f.txt"])["f.txt"].created` deep-equals
  `getFileLatestModified("f.txt").created`.

### Step 2 — Docs

Update doc comments (Rust `///`, which regenerate into `index.d.ts` via
`yarn build:debug`) so the public API documents `created`'s semantics per
GC5/GC6: oldest commit that first added the file; delete→re-add returns the
original add; merges included; no rename-follow; exact-path resolution with the
single-file glob/directory caveat (`created` may be `null` then). Cover it on the
`FileModification.created` field, `CommitInfo`, `get_file_latest_modified`, and
`get_files_latest_modified`.

Then `yarn build:debug` (regenerate + commit bindings), `yarn test` — full suite green.

### Done when

`yarn test` is fully green including the new semantics tests; docs describe
`created`; bindings regenerated and committed.
